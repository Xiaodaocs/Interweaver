# 01 · 产品概念与定位

## 1. 愿景

> 知识永远都在那里。它们看似分散开来，但是其实相互有关联。
> 用户，是在探索中把它们交织起来的那个人。

**交织者（Interweaver）** 是一个以"探索"为第一性的数学沙盒网站。它既不是课件，也不是题库，也不是工具软件——它是一张**有数学灵魂的电子草稿纸**，配上一个**告诉你"你刚刚发现了什么"的成就系统**。

当用户百无聊赖地随手画了个圆，又让一根线绕它转起来时，系统会告诉他：你刚刚点亮了「弧度制」；当他把正弦波和圆用变量连在一起、看到波形从圆周上"长"出来时，系统会告诉他：你刚刚把「三角函数」和「圆」织在了一起——而这张网上的每一条连线，都是他亲手接上的。

## 2. 宗旨（产品存在的理由）

1. **让用户在数学中遨游**，而不是被数学驱赶。没有课程表、没有对错判定、没有进度条压迫。
2. **让身体先于符号理解数学**。拖一拖、转一转、连一连，先获得直觉，符号只是直觉的速写。
3. **让"知识是一张网"成为用户的亲身体验**，而不是一句被灌输的比喻。产品的一切机制（关联、联动、成就连线）都在让用户亲手织网。

## 3. 定位：三选一陷阱与我们的答案

数学软件历史上只有三种成功形态，交织者必须明确自己**不是什么**：

| 形态 | 代表 | 本质 | 我们不做它的原因 |
|------|------|------|------------------|
| **教学工具** | GeoGebra、Desmos | 老师做课件、学生完成作业 | 以"任务"为中心，无探索欲；界面为功能堆叠服务 |
| **课程产品** | Brilliant、可汗学院 | 被设计好的学习路径 | 用户是"乘客"不是"探险家"，与"遨游"宗旨相悖 |
| **解题游戏** | Euclidea、DragonBox | 给定关卡，寻找最优解 | 有标准答案 = 关闭了自由；关卡耗尽即流失 |

**交织者的定位：数学沙盒玩具（Math Sandbox Toy）。**

类比关系：

- Minecraft 之于积木与工程 ≈ 交织者之于绘图与数学
- Besiege / Zachtronics 之于机械与编程 ≈ 交织者之于函数与几何
- 它的"玩法"不是被发明的，而是数学本身固有的：**构造、变换、关联、发现**。

玩具 ≠ 浅薄。一个好玩具的标准是：**三岁能上手，三十岁不无聊，且深度来自真实世界的物理**——交织者的"物理"就是数学本身，因此它的深度天然无穷。

## 4. 目标用户画像

| 画像 | 描述 | 他们在这里做什么 |
|------|------|------------------|
| **好奇的学生**（14–22） | 课上听不懂函数/导数，对"数学有什么用"无感 | 拖拖滑杆突然看懂 sin 的波长是什么；为了点亮成就主动研究 |
| **消遣型探索者**（18–35） | 喜欢 Minecraft/Factorio/解谜游戏，有智力消遣习惯 | 下班后随手搭一个"用圆周运动画李萨如图形"的玩具，获得心流 |
| **数学爱好者/老师** | 想把脑子里的直觉变成可视化 | 用手搓演示器替代 PPT，分享作品链接 |
| **成就猎人** | 被收集欲驱动 | 试图点亮整张知识网，钻研"这个成就到底怎么触发" |

一期主攻 **消遣型探索者 + 好奇的学生**：他们决定留存；爱好者决定内容生态。

## 5. 核心体验循环（Core Loop）

```
        ┌────────────────────────────────────────────┐
        ▼                                            │
  随手画点什么 / 拖出一个预设          （心流，无目标压力）
        │
        ▼
  给它接一根线（变量、关联、约束）  ←—— 产品最核心的动作
        │
        ▼
  拖动滑杆 / 拖动图形 → 看到联动      （"啊哈"时刻）
        │
        ▼
  ✦ 系统识别出你发现了什么 → 成就点亮 + 形状冒光
        │
        ▼
  成就页：知识网上一个节点亮起，若与旧知识同用 → 连线亮起
        │
        └──── "我想看看还能织出什么" ────→ 回到画布
```

这个循环的每一环都对应一个功能模块：

| 环节 | 功能模块 | 文档 |
|------|----------|------|
| 随手画 | 电子草稿纸 + 工具组 + 预设库 | 02 章 §2–§4 |
| 接线 | 变量滑杆 + 绑定引擎 + 约束系统 | 02 章 §5–§7 |
| 联动 | 响应式计算图 + 反向求解 | 02 章 §6 |
| 发现 | 函数生成器 + 观察器 + 微积分工具组 | 02 章 §8–§10 |
| 反馈 | 成就检测引擎 + 视觉反馈 | 03 章 |
| 织网 | 知识网可视化 | 03 章 §6 |

## 6. 设计哲学（写进团队 DNA 的五条）

1. **原语极简，组合无穷。** 每想加一个新功能，先问：能不能用现有原语组合出来？能，就不加——把它做成一个**成就**或**模板**，让用户自己搭出来。
2. **画布不拦人。** 永远可以直接下笔。所有数学语义（"这是一个三角形"）由系统在后台识别，绝不用模态弹窗、向导、必填表单打断心流。
3. **错误不存在。** 没有"你画错了""解不出来了"的红字。画歪的线也是线；无解的约束以温柔的视觉降级呈现。探索产品里没有惩罚。
4. **一根线讲清所有事。** "关联"是产品唯一的核心隐喻。变量↔图形、函数↔几何、成就↔成就，全是连线。UI 里一切联动都必须"看得见那根线"（连接视图）。
5. **震撼要留给顿悟。** 平时界面安静得像一张白纸（Apple 式的克制）；但当用户完成一次"交织"，反馈要不惜成本地绚烂——让多巴胺奖励的是"理解"，不是"点击"。

## 7. 与核心竞品的一句话区隔

详见 [07-风险难点与竞品分析](./07-风险难点与竞品分析.md)。

- **GeoGebra** 是教师的备课本 → 交织者是玩家的草稿纸。
- **Desmos** 是表达式的计算器 → 交织者是图形的游乐场。
- **Polypad** 是教具盒（给你摆好的积木） → 交织者是物理沙盒（积木自己会动、会联动）。
- **Euclidea** 给你题目 → 交织者给你宇宙。
