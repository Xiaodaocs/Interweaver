## 1. 视觉系统（深色宇宙）

### 1.1 主题与默认值

- **默认深色**：`主题 = deep-space`（首选项持久化；提供 浅色/深色/跟随系统 三选，默认深色）。
- **画布本身也进深色**：网格线改为低对比冷灰（`#2A2E3A`），纸面 `#0B0E16`，实体颜色在深底上**提亮 12% 饱和度**（现有 8 色调色板需要一套 dark 变体）。

### 1.2 发光与"散光"（bloom）

三层叠加，全部用 canvas 合成而非滤镜（性能可控）：

1. **核心层**：实体/节点本体（清晰、1px 描边）。
2. **内辉**：同形状放大 1.15×、`globalAlpha 0.35`、色相不变。
3. **外散**：放大 2.2×、`globalAlpha 0.12` + `shadowBlur 18`，仅对**已点亮**与**悬停/选中**对象绘制（未点亮不发光 → 形成"暗星 vs 亮星"的对比）。

> 预算：1000 实体场景下，只对"点亮/悬停/选中"对象做外散；其余对象只画核心层。这条写进性能核验。

### 1.3 动态细节

- **呼吸**：点亮节点以 3.2s 周期做 ±4% 的亮度脉动（相位按节点 id 哈希错开，避免整体同步闪）。
- **流动光点**：织边上的光点沿路径运行（已有），强度越高越密。
- **扫光**：成就达成瞬间，一道细光带从卡片左侧扫过（220ms）。
- **入场编排**：从"你的焦点星"向外逐层淡入，每层 70ms；`prefers-reduced-motion` 下全部静态。

### 1.4 星空背景（~~默认开启，可关~~ → **已按用户要求删除**）

> ★ **现状**：用户后续要求"**删掉『星空』的背景逻辑（之前曾经加到过成就页面里）**"，于是成就页的星场逻辑与容器
> 都已移除（`app/src/starmapMain.js` 的文件头注释记着这次删除；`render.js` 里工作台那份更早已移除）。
> 下面这段保留为历史设计，**不再对应实现**；`styles.css` 里的 `.bgStars` 规则成了遗留死规则（尚未清理）。

- **三层视差星场**：远（800 颗、0.6px、极暗）/ 中（300 颗、1px）/ 近（60 颗、1.4px、带十字光晕）。
- **微闪烁**：每颗星独立相位与频率（0.08–0.35Hz），用"亮度表 + 相位"预计算，逐帧只做加法 → 1000 颗星 <0.4ms。
- **缓慢漂移**：整体 60s 横移一个屏幕宽度的 3%（几乎察觉不到，但"活"）。
- **星云**：两张极低对比的径向渐变（深蓝/紫）叠在最底层，营造纵深。

## 2. 布局：从"表格"到"呼吸的网"

> ★★ **这一节（含 §2.1–§2.4 与 §3 的走线）已被用户后续要求整体替换，正文只作历史设计保留。**
> 用户原话："**知识卡片还是旧的排列方式，现在看上去很乱。请完全重新排序知识卡片的位置，类似神经网络那样从左往右。**"
>
> **现在的实现（`app/src/starmapLayout.js` 的 `layoutNeural`，由 `starmap.js` 的 `layoutStarMap` 调用）**：
> - **X = 难度层，严格分列**（左易右难）—— 同一列的列心严格对齐；**不再有层内抖动**、**不再有组带引力/软组带**、**不再跑松弛迭代**（位置是解析算出来的，确定性、可复现、可测试）；
> - **Y = 列内等距 + 整列垂直居中**（每列的纵向中心落在画布中线上）；
> - 列内排序：先按分组（同组连续，"读起来仍是一撮"），组内按 id；
> - 保留"浮动感"：每张卡片有 **±18px / ±16px 的确定性微抖动**（由 id 哈希决定，每次打开位置一致）——它取代了原来的"层内抖动 + 松弛"；
> - 画布尺寸按列算宽、按最高列算高：实测 **2712×2350**（旧布局 4658×6188）；
> - 判据（`tests/layout-columns-check.mjs`，已在 verify 链里）：① 最小中心距 ≥46px ② 卡片矩形**不重叠** ③ 同列横向散布 ≤2×JITTER_X ③b 列内行距下界 ≥ 卡片高+20px ③c 各列基本居中 ③d 同组在列内连续 ④ 列号与难度层一一对应 ⑤ 65 个知识点都有位置；
> - 卡片尺寸也进了判据：一档 54×70 / 二档 62×76 / 三档 72×82（`CARD_BOX`），卡片之间要求净距 ≥ `CARD_PAD(20)`。

### 2.1 分层骨架（保留难度方向，但不做硬网格）

- 仍然 **X ＝ 难度层**（L0 最左 → L6 最右），因为"左易右难"是你要的语义方向。
- 但**不再严格等距对齐**：列宽 `W = 216px`，实际 X 加 **层内抖动** `dx ∈ ±26px`。
- **Y 不再按组严格对齐**：组只提供"引力中心"（四条水平带），每个节点在其组带内做**软约束**分布：`y = 带中心 + (组内序号 - 组内均值) × 52px + dy`，`dy ∈ ±22px`。
- **不歪到看不出同组**：同组节点保持 ≈同一条带（带的可见渐变背景 + 连线只在同带内用"同族色"），视觉上"稍微岔开但一眼仍是同类"。

### 2.2 呼吸感的三条量化规则

1. **同层最小间距**：≥ 46px（防止挤在一起）。
2. **偏移幅度**：`|dx| ≤ 层宽×12%`、`|dy| ≤ 组带高×18%`（保证"岔开"但不失控）。
3. **确定性抖动**：用 `hash(nodeId)` 生成偏移（不是随机）——同一份数据每次打开**位置一致**（可复现、可测试），但仍显得自然。

### 2.3 松弛（防重叠）

- 先按上述规则出初始位置，再跑 **40 次迭代的力导向松弛**，只保留三个力：
  - 排斥：任意两节点距离 < 96px 时互推；
  - 弹簧：依赖边两端保持 180–260px；
  - 锚定：向初始位置回拉（权重 0.08，防止整张网漂走）。
- 松弛结果缓存（数据不变则不重算）；新成就点亮时只对受影响子图做 15 次局部迭代（增量，不重排全图）。

### 2.4 一列塞不下时怎么办（T2 实施中发现，**需拍板**）

**问题（实测数据）**：现在 57 个节点 / 7 个层列 / 4 个组带。硬约束"同列相邻竖直间隔 ≥46px"意味着
**一列装 25 个节点就需要 ≈1150px 竖直空间**，而 4 条组带只有 4×152 = 608px。二者不可能同时满足：
节点要么溢出自己的组带（实测溢出 261px），要么把组带越撑越高（画布从 1338 涨到 3079px）。

§2.1/§2.2 只规定了"间距"与"同组可辨识"，**没有规定溢出时的规则** —— 必须补上。三个选项：

| 选项 | 规则 | 代价 | 与其它约束的关系 |
|------|------|------|------------------|
| **A · 列内分道（推荐）** | 一列太挤时在该层内开 **2–3 条竖直子道**（左右错开 `NODE_W×0.8+16`），列宽按子道数加宽 | 画布变宽（约 2100–2600px） | 三条不变量全满足；子道错落本身就是"不完全对齐"的呼吸感，且配合"打开时大到看不全貌" |
| B · 拥挤列降低间距 | 只对拥挤列把最小间距降到 34–38px，其它列仍 ≥46 | 需放宽 §2.2 的断言表述 | 与"≥46px"字面冲突 |
| C · 组带自由生长 | 接受组带被撑高、画布变高（实测 3079px） | 纵向很长，"同组一条带"的观感被拉长 | 不变量满足，但观感与"呼吸感"目标相悖 |

**已拍板（用户决定）：采用 A（列内分道）**，理由：它是唯一同时满足"≥46px 间距 / 同层仍同层 / 同组仍成带"的方案，且"子道错落"正是"自由又密切、但不乱"的效果。
落地规则（实现依据）：
- **每列的宽度随"子道数"变化**：`宽 = NODE_W + (L−1)×NODE_W×0.6 + 2×MAX_DX + 走廊(56)`
  - L=1（不挤）→ **258px**（与 §3.1 的 α 一致）
  - L=2 → **348px**；L=3 → **438px**
- **子道数**由该列最挤的格子决定：`L = ceil(格内所需竖直跨度 / 该组带可用高度)`，所需跨度 = `(格内节点数−1)×46 + 2×margin`
- 同一格内的节点按**子道轮转**（确定性：按 id 排序后轮转），子道横向偏移 `(i − (L−1)/2) × NODE_W×0.6`
- 三条不变量（§2.2 的间距、无重叠、带内归属）**保持不变**，不因为分道而放宽

## 3. 走线：Minecraft 成就系统那种"多而不乱"

> ★★ **本节（正交走线 + 车道 + 障碍绕行 + 跨线拱桥）已整体作废**：正交布线模块 `edgeRouting.js` 已**删除**，
> 用户随后要求"连线改成神经式曲线"。**现在的实现**（`app/src/starmap.js`）：
> - 卡片之间是**贝塞尔弧线**（微波状，最大偏离 ≤46px），**允许交叉**，**线在最底层**（不压卡片）；
> - **没有车道分配、没有障碍绕行、没有跨线拱桥**（拱桥数必须是 **0**）；
> - **长跳边尽量"逐层"**：在**图谱里本来就存在的真实关系**（依赖边 / 相关边）构成的图上，找一条从左往右的链把它拆成若干跳；
>   **找不到语义链就保留原来那条直达边**（用户明确要求"如果没有就只能直接连"），**绝不编造中转**（`routeByLayers()` 有 `fakeHop` 自检）；
> - 实测：原始依赖边 80 → 拆后 73 跳（拆开 9 条 / 保留直达 71 条 / 编造 0 条），相关边 9 条；
> - 选中卡片时**只亮"它 + 它的直接邻居"**（用户后续修正：以前是整片连通域全亮，"因为线全部连起来了"）；
> - 断言在 `tests/check-starmap-neural.mjs`、`check-starmap-layers.mjs`、`check-line-visibility.mjs`、`t3-starmap-check.mjs`（要求 polyline = 0、拱桥 = 0）。
>
> 以下为历史设计：

**不用直线直连**，改用**正交（曼哈顿）走线 + 车道分配 + 障碍绕行**：

1. **端口**：每个节点按目标方向选择出口（左→右的边从右侧 3 个端口之一出：上/中/下，取"最不拥挤"的那个）。
2. **车道（lane）**：列与列之间划分 `k` 条水平车道（`k = 6`，间距 26px）。一条边由 `出口 → 竖直段 → 车道 → 水平段 → 竖直段 → 入口` 组成（标准 Z 形/L 形）。
3. **车道分配**：同一车道内若已有边，则换下一条；若全满，则在两条边之间**插入子车道**（间距 13px）。
4. **障碍绕行**：节点占据矩形（含 8px 内边距）作为障碍；走线若穿过障碍，则在障碍上方/下方选一条空车道重路由（最多重试 6 次，仍失败则允许穿过但降透明度 0.45 并在交点画"跨线小拱桥"，Minecraft 风格）。
5. **交处理**：不同边的**水平段互不重叠**（车道保证）；水平段与竖直段相交处画 **2px 小拱桥**（一条边跨过另一条），一眼能看出"这是两条线"。
6. **颜色与粗细**：依赖边 `--locked` 灰细（1px）；织边 `--gold` 按强度 1.2/2.0/3.0px；相关边虚线。**同一节点引出的边在其端口处做 8px 的圆角过渡**，避免"直角扎堆"。
7. **可见性规则**（防糊）：镜头缩放到 < 0.55 时，**只画织边**（依赖边淡出）；悬停某节点时，**只保留它的边**（其余降至 0.12 透明度）。

## 4. 成就形状与手绘图标（三档，一眼看出等级）

| 档 | 覆盖 | 形状 | 尺寸 | 内嵌手绘 SVG（不能用图片素材，全部路径手写） |
|----|------|------|------|---------------------------------------------|
| **I 火种**（L0–L1） | 最基础构造 | **圆形** | 直径 46px | 点：一个实心点；线：一段斜线；圆：正圆 + 圆心点；变量：滑杆 |

## 5. 默认视野：大到看不到全貌

- 打开成就页时：`zoom = 1.6`（而不是 fit），镜头**对准最近点亮的那一颗**（没有则对准 L0 区域中心）。
- 右上角提供：`⌖ 回到我的星`、`⤢ 全览`（缩到 fit）、`＋/－` 缩放。
- 首次打开播一个 700ms 的"从 2.4× 缓推到 1.6×"的入场（reduced-motion 下直接静态 1.6×）。
- 效果：**一屏只能看到 8–14 颗节点**，剩下的在视野外 → 需要缩小/拖动才能看到全貌（正是你要的"大"）。

## 6. 成就内容体系：原计划 100 条（A 72 / B 28） → **实际落地 134 条（A 114 / B 20）**

### 6.1 扩容方向（每条都"可判定"，不写里程碑式的空话）

| 新增组 | 条数 | 例子（判据都是实测值） |
|--------|------|----------------------|
| 圆与弦族 | 10 | 弦心距等于某个已知量、两条弦等长、圆内接四边形对角互补（±0.5°） |
| 三角形族 | 8 | 等腰（两边等长 ±1%）、等边（三边 ±1% 且每角 60±0.5°）、直角+中线=半斜边 |
| 变换族 | 8 | 旋转对称：图形绕某点转 180° 后与自身重合（顶点集合误差 ≤1%） |
| 函数族 | 12 | 偶函数（f(-x)=f(x) 采样 ≤1%）、周期（f(x+T)=f(x)）、单调上升采样 |
| 微积分族 | 8 | 切线斜率与差商一致、积分值随 n 单调趋于解析值、极值点切线水平 |
| 绑定与联动族 | 8 | 三级链 A→B→C 联动、一个变量驱动 ≥3 处、反向求解成功 |
| 约束族 | 8 | 完全约束（自由度=0）、过约束被求解器纠正、相切+同心 |
| **非数学主线（彩蛋）** | 10 | 见 §6.2（**不标注"非主线"**，混在正常成就里） |

### 6.3 文案分级规范（Minecraft 味道）

- **火种级**：≤14 字，口语、轻快。例：「第一个点」「点到线，一步」「直角：最稳的那个角」
- **结构级**：一句半，带一点"顿悟感"。例：「三条边首尾相接，于是有了一块能算的面积。」
- **交织/巨匠级**：**史诗**。用两段式：第二人称 + 一个世界的比喻。
  - 例（欧拉之环）：「你把圆、波与同一个变量拴在一起。**于是在你的画布上，转动与振动成了同一件事的两种称呼。**」
  - 例（微积分的钥匙）：「**你同时握住了瞬时与累积。**从今往后，曲线不再只是一条线，而是它自己变化的历史。」
- **彩蛋级**：幽默、克制、不解释笑点（见 §6.2）。
- **统一规则**：标题 ≤6 字；flavor ≤48 字；不用"恭喜/太棒了"；不出现"成就"二字。

## 7. 详情与"当时的图片"

### 7.1 解锁瞬间的画面快照（关键技术点）

- 达成时（`tracker` 授予的那一刻）：
  1. 从**画布 canvas** 取一张缩略图：`drawImage` 到 320×200 的离屏 canvas（等比裁剪，居中于"触发该成就的实体群"的包围盒中心）；
  2. `toDataURL('image/jpeg', 0.72)` → 约 12–25KB；
  3. 与成就记录一起写库（`IndexedDB.scenes` 同库分 store `shots`，或并入进度对象；**导出时含图**，文件会变大 → 导出对话框给"含截图/不含截图"两个选项）。
- 失败兜底：`toDataURL` 抛错或超时 → 记录 `shot: null`，详情页显示"当时没留下画面"（**不阻塞成就**）。

### 7.2 详情卡（点击节点/成就打开）

```
┌───────────────────────────────┐
│  ⬡  欧拉之环        [交织 · T3]│  ← 形状+档位标识
│  ─────────────────────────────│
│  【当时】  320×200 快照（点击看大图）│
│  【如何触发】 …判据的人话版…        │
│   · 需要先点亮：圆 / 变量 / 第一次关联│
│  【它代表什么】 史诗文案一段         │
│  【当时的数据】 证据数值（可复核）    │
│  ─────────────────────────────│
│  [回到那个场景]  [知道了]     ⠿   │  ← ⠿ 可拖动卡片
└───────────────────────────────┘
```

- **已激活**：显示快照 + 判据 + 依赖 + 证据数值 + 达成时间 + `回到那个场景`（载入当时的场景快照，复用已完成场景序列化）。
- **未激活**：只显示形状（灰）、标题（模糊/问号可选）、以及**一句暗示（≤22 字）**，例：
  - 「把一个变量同时接到圆和波上会怎样？」
  - 「让割线的两点互相靠近，直到它们几乎重合。」
  - 「画一个四边等长、还有直角的四边形。」
- **卡片可拖动**：`⠿` 拖动手柄，位置持久化（`localStorage: ach.cardPos`），双击 `⠿` 复位。

### 7.3 暗示库维护规则

每条成就**必须**在数据里带 `hint` 字段（未激活时显示），并进单测：**所有成就都有 hint、长度 ≤22 字**（防止漏写）。

## 9. 音频：空灵、悠长、神秘（原创合成，零版权素材）

> 你推荐 C418 的听感方向（空灵、极简、长尾、克制），但**我不会引用任何受版权保护的音频文件**。做法是用 **WebAudio 实时合成**一段可无限播放的环境音，风格对齐"空灵/悠长/神秘"。

- **织体**：3 个正弦/三角波声部构成缓慢移动的和声垫（根音 + 纯五度 + 九度），音量 -28dB 起步。
- **随机化**：每 20–40 秒随机换一次和弦（从 6 个和弦的池子里选，避免小调刺耳），加 1.8s 交叉淡入淡出。
- **点缀**：每 8–20 秒随机一个"风铃"音（高八度正弦 + 4s 指数衰减 + 轻混响 impulse 生成的低通噪声），音量 -34dB。
- **混响**：用 `ConvolverNode` + 程序生成的噪声脉冲（衰减 3.2s），营造空间。
- **低音**：一个 55Hz 正弦以 ±0.4dB 呼吸（"悠长"的底）。
- **规则**：
  - **默认开启**（用户最终拍板；见 `ambientAudio.js` 文件头"默认开启"）：进入即尝试启动；被浏览器自动播放策略拦下时，挂一次性手势监听（用户第一次点击/按键即启动），并在 UI 给出"点击 ♫ 开启"的提示；状态持久化在设置库；
  - 页面隐藏 / `prefers-reduced-motion` / 用户离开成就页 → 淡出（1.2s）；
  - 所有节点在一条 `GainNode` 下，随时可 0 延迟静音。
- **性能**：音频完全在音频线程，主线程只做 20s 一次的调度。

## §11 收尾期的三项决定（按实施者的判断采纳，待用户可随时推翻）

这三项在实施中都遇到了"设计要求之间互斥"或"成本与收益不成比例"的情况，已按以下方式采纳并记录理由。
用户若不同意，改回的成本都很低（各自只影响一处参数或一个渲染分支）。

### §11.1 「枢纽密 / 叶端散」——取消几何指标，改为**视觉权重**

**实测数据**：枢纽（依赖度 ≥3）的邻居**天然分布在不同难度层**（相距 1–5 列），
列距 258–438px ⇒ 实测「枢纽邻居均距 / 叶端邻居均距 = **2.64**」，而指标要求 ≤0.75。
**结论：在"层 = 难度"的分层布局里，几何上的"枢纽更紧凑"不可达**（与"带内归属 ⟂ 画布高度"同类）。

**采纳**：取消该几何指标；改为**视觉权重** —— 枢纽节点与其连线在视觉上"更重"（更亮的辉光、更粗的线），
从而在观感上形成"这里是一团重要的东西"，同时不违反分层语义。

### §11.2 长边曲线占比上限：25% → **35%**

**实测数据**：§3.2「组间散 ≥120px」与 §3.4「曲线 ≤25%」**互斥** ——
拉开组带后长边需跨越的竖直距离变大，更多边触发曲线回退（实测 19% → 27%）。
**采纳**：上限调至 35%，并在断言注释中写明调整理由与真实百分比（可见、可复核）。
依据是用户的明确指示"**实在做不出来就使用曲线重新排列**"；25% 是实施者自定的技术指标，非用户要求。

### §11.3 C5「收窄画布」——**暂缓**

**实测数据**：① 封顶组带高度后画布可从 3258px 降到 **1127px**，但最小间距被压到 **7.9px** ✗；
② 原因：当前布局的**纵向余量为零** —— 最贴边的 15 对节点全部是"同列同组同子道"，dy 恰为 **46.0–46.8px**；
③ 换言之「间距 ≥46px」与「画布更矮」在当前密度下**直接竞争**，要两者兼顾需要一次**全局重排**。

**采纳**：暂缓。理由：用户的原始要求是"**打开时大到看不到全貌，需要缩小才能看到**"，
而当前 2845×3258 的画布 + 默认 1.6× 相机（首屏 10/57 节点）**已经满足该要求**；
把画布压小反而与目标相悖。若日后需要更紧凑的地图，再做全局重排。
