## 0. 设计原则（先定死，后面所有条目都服从它）

1. **每个成就都必须"可被程序判定"**，判据只依赖画布上可测量的事实（实体、参数、绑定图、约束、观察器），不依赖"用户说自己懂了"。
2. **不制造假阳性**：判据要能区分"碰巧"与"真的做到"。例如"做出直角"必须是**真的量出 90°**，而不是"画了一条看起来竖的线"（容差 0.5°）。
3. **成就只奖励"创造"，不奖励"删除"**：删除实体不撤销已点亮的成就（存一次性事件），但**撤销后重新校验**只用于"连线"的合法性（见 §3.4）。
4. **可解释**：每个成就卡片必须能回答三件事：**做了什么、凭什么判定、对应哪个知识点**（附当时的数值证据）。
5. **知识网只连"有意义的串联"**：连线不是装饰，每条连线必须对应"你先掌握 A，才可能做到 B"的真实依赖，或"A+B 组合出 C"。

## 3. 串联（连线）规则 —— 这是本阶段最关键的部分

### 3.1 连线来源分两类

- **依赖连线（必修链）**：A 是 B 的前置。当**两端都点亮**时自动点亮连线。例：N1→N2（先有点，才有线上点）。
- **组合连线（成就连线）**：由**某条成就**在达成时**显式**点亮，代表"你把两件事拼起来了"。例：B5 达成时点亮 N6—N10（角 × 角度驱动）。

### 3.2 依赖连线表（19 条，全部为"两端点亮即亮"）

```
N1→N2  点 → 线上点          N2→N3  线上点 → 绑定
N3→N4  绑定 → 接点绑定      N3→N5  绑定 → 参数联动
N1→N6  点 → 角（先会放点）  N6→N7  角 → 只认真实相交
N6→N8  角 → 垂直            N8→N9  垂直 → 平行与重合
N6→N13 角 → 角的方位        N6→N10 角 → 角度驱动
N10→N11 角度驱动 → 绕交点旋转   N11→N12 旋转 → 反向求解
N2→N14 线上点 → 多边形      N15→N16 约束求解 → 相对参照
N15→N17 约束求解 → 矛盾与优先级  N14→N20 多边形 → 积分
N18→N19 导数 → 极限         N19→N20 极限 → 积分
N18→N21 导数 → 函数与导数
```

### 3.3 组合连线表（12 条，由成就显式点亮）

| 连线 | 由哪条成就点亮 | 为什么这么连 |
|------|----------------|--------------|
| N4—N13 | A4 + B8 | 接点绑定与"角的方位"合起来＝在真实交点上精确取角 |
| N5—N11 | A5 + B6 | 端点跟随 + 绕交点旋转＝"点跟着线转" |
| N7—N17 | B2 + C4 | 只认真实相交 + 冲突拦截＝"不做无意义的几何" |
| N10—N19 | B5 + D2 | 变量驱动 + 割线趋近＝"用参数看极限" |
| N12—N15 | B7 + C2 | 反向求解 + 约束求解＝两个方向的力量要协调 |
| N16—N17 | C3 + C4 | 相对参照 + 矛盾优先级＝参照选错就会打架 |
| N3—N10 | A3 + B5 | 双端绑定 + 角度驱动＝被驱动的量不能再被手改 |
| N9—N8  | B4 + B3 | 0/180 与 90 是同一套"射线关系"的端点情形 |
| N14—N21 | C1 + D4 | 多边形与导函数＝面积/形状的变化率 |
| N20—N21 | D3 + D4 | 积分与导数＝互逆 |
| N2—N12 | A2 + B7 | 线上点 + 反向求解＝"拖着看上游怎么变" |
| N6—N4  | A4 + B1 | 接点 + 角＝交点是角的顶点 |

### 3.4 合法性与防抖（避免"刷成就"）

- 连线只在**当帧成立**时点亮，且需**连续 3 帧**满足（防抖），并**记录证据快照**（当时的关键数值）。
- 依赖连线永不熄灭；组合连线在**证据不再成立**时**变暗（保留历史，标记"已撤销"）**——不删除，避免"删一个点整张网崩"。
- 同一成就只记一次时间戳；重复达成只更新"最近一次"。

## 4. 检测方案（工程实现）

### 4.1 数据流

```
每帧：S.ensureEvaluated(st) 之后 → checkAchievements(st)
  ├─ 收集"事实快照"：实体类型/数量、绑定图（谁驱动谁）、角度实体读数、约束残差、观察器值
  ├─ 逐条评估 16 个成就的判据（纯函数，输入 = 快照 + 历史环形缓冲）
  ├─ 新达成 → 事件队列 [{id, at, evidence}]
  └─ 点亮节点/连线 → 事件队列 [{node|edge}]
```
- **纯函数 + 快照**：便于单元测试（不需要浏览器），也让"判据"可被单独复核。
- **历史缓冲**：每帧只保留最近 30 帧的关键量（用于"连续 3 帧""单调趋近"这类判据）。
- **持久化**：先做**内存态**（本阶段），P13 再做 localStorage 持久化（跨会话保留成就与知识网）。

### 4.2 接入点（不侵入业务代码）

| 位置 | 做什么 |
|------|--------|
| `state.js` 的 `emit(st, kind)` | 已有的事件总线；新增 `kind='achievement'` 事件 |
| `main.js` 的帧循环 | 每帧末尾调用 `achievements.tick(st, dt)`（内部有节流：每 4 帧才算一次，避免影响性能） |
| `tools.js` 的手势结束 | 记录"被拒提示"（B2/C4 需要"曾失败过"这类事实） |
| `panel.js` / `menu.js` | 只消费成就事件（弹卡片、画知识网），不改判定 |

### 4.3 检测的"可辩解性"要求（每条成就都要能自证）

成就卡片上必须显示**当时的证据**，例如：
- B5：`角度 90° → 30°（变量 a: 90 → 30）`
- B6：`绕交点 (0.00,0.00) 旋转；线长 4.243 → 4.243`
- D3：`n=4→12→40：误差 0.42 → 0.11 → 0.01`

## 5. 前端设计（先设计，后开工）

### 5.1 三个界面

**(1) 成就卡片（toast）** —— 达成瞬间从**右下角**滑入（避开左下设置区、右上帮助）：
```
┌─────────────────────────────┐
│ ✦ 成就 · 绕那个交点转        │
│ 角度驱动的旋转是"绕交点"，   │
│ 不是绕中点。                │
│ 证据：交点 (0.00,0.00) 未动 │
│ 长度 4.243 → 4.243          │
│            [看知识网] [知道了]│
└─────────────────────────────┘
```
- 尺寸 320px，纸白玻璃底、1px 发丝边、圆角 16px；3.2s 后自动淡出（可点"知道了"立刻收）。
- 同一时刻最多 1 张；排队显示，间隔 0.6s。

**(2) 知识网（星图）** —— 从工具栏/成就卡片进入，**全屏浮层**：
- 布局：**分组聚类**（4 组各占一区，组内按依赖深度分层），节点＝圆点（点亮实心/未点亮空心灰），连线＝细线（依赖连线灰、组合连线**暖黄**）；点亮的连线带**微弱流动光点**（表示"通了"）。
- 交互：悬停节点 → 高亮它的所有连线 + 右侧浮出"这个知识点是什么/由哪条成就点亮"；点击节点 → 下方列出相关成就与证据；`Esc` 关闭。
- 进度：顶部一行 `已点亮 12/21 知识点 · 9/31 连线`。

**(3) 成就面板（列表）** —— 与知识网同一浮层的第二个页签：16 条成就按组排列，已达成显示证据与时间，未达成显示**提示性判据**（例如"让某条线与另一条线成 90°"）。

### 5.2 视觉规范（Apple 极简，与现有风格一致）

- 颜色：纸 `#F5F5F7`、墨 `#1D1D1F`、次要 `rgba(60,60,67,.6)`、强调 `#5E5CE6`、**达成暖金 `#C9A227`**、组合连线暖黄 `#E3D68C`（与角小球同色系）。
- 动效：节点点亮 220ms 缩放+淡入；连线点亮 400ms 沿路径"生长"；overlay 淡入 180ms。全部走 `prefers-reduced-motion` 时关闭。
- 不做弹窗堆积：成就卡片与知识网都不阻挡画布操作（浮层可穿透点击背景关闭）。
