## 三、代码逻辑复核（找到并修掉的真问题）

1. **幽灵类 `smTick`**：CSS 删除后 JS 仍在窄屏列表模板产出 → 该标记失去样式。**双向核对（产出 ↔ 定义）**才发现；
2. **`smRing` 死规则**：枢纽外环高亮规则从未生效（徽标 SVG 的环没有 class）→ 处置是**激活**（补 class），而不是删规则（它属设计 §11.1）；
3. **居中失效的真正根因**：`@keyframes smIn` 的 `to { transform: none }` **覆盖**了 `translate(-50%,-50%)`（动画声明优先级高于普通声明）→ 此前用 `!important` 只是治症状，改动画才是治根；
4. **核验随契约更新**：节点标记由 `<b>` 改为 `<span class="smCap">` 后，T3 核验脚本仍读 `<b>` → **假红灯**（400 vs 400）。契约变了，所有引用它的核验都要一起改；
5. **我自己写错的一条补遗**：深色补遗里写了 `:root[data-theme="dark"] .cl-body, .cl-item`，而清单实际用 **id**（`#clBody`）→ 该规则从未生效（等于新增死规则）→ 改为 `#clBody` 后清单深色文字色才真正生效。

## 五、已知未覆盖清单（22 条，逐条归因）

这些类**只在特定交互状态下渲染**，普查未覆盖到 —— **不是待删的旧样式**：

- **关联向导 8 条**：`wizTabs / wizTitle / wizSub / wizParam / wizVarBtn / wizCancel / done / switch`

## 六、这一阶段的方法学教训（已并入 `P15-附二-实施复盘.md`）

1. **静态扫描抓不到动态拼的类**（`class="${cls}"`、`mkPoly(...,'smDep')`、`setAttribute`）→ 类契约必须**运行时普查**；
2. **普查必须覆盖界面**，否则"死规则"全是假阳性（最初 44 条中 18 条一开界面就消失）；
3. **阈值要取稳定上界**（该计数在 22–23 间波动；用单次采样值做基线 → flaky 断言）；
4. **巡检工具必须快**（早期版本点几十个按钮 >10 分钟 → 进不了回归；瘦身后 16 秒）；
5. **工具要先独立跑稳再入队 verify**，且**崩溃必须打印 message**（此前只留栈帧，白花两轮才发现是 `protocolTimeout`）；
6. **写文件禁止用内联命令**（内联 `node -e` 被 shell 拆坏 3 次）；**补丁脚本内部同样禁止嵌套引号**（第 4 次同类错误的规则收紧）；
7. **提交前必须确认 `verify` 退出码为 0**；红状态提交时必须在提交信息里写明失败阶段与原因。
