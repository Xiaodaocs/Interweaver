# 05 · 实施路线图（P1 – P20）

> 20 个里程碑，分五幕推进。排序原则：**风险最高的技术假设最先验证，产品的"魔法时刻"最早跑通，内容/生态最后放量。**
>
> 工期按 1 个标准小队（2 前端 + 1 全栈/后端 + 0.5 设计 + 0.2 PM）估算，单位为人周（pw），仅供排期参考。

---

## 0. 技术选型基线（P1 前确认）

| 层 | 选型 | 理由 |
|----|------|------|
| 框架 | React 18 + TypeScript + Vite | 生态、招聘、HMR 效率 |
| 画布渲染 | 自研 Canvas2D 场景渲染器 → P17 评估迁移 WebGL（PixiJS） | 一期实体量 Canvas2D 足够且文本/抗锯齿省心；接口抽象使渲染器可替换 |
| 表达式 | mathjs（解析）+ 自研 AST → 可微/可逆性分析 | 避免自造解析器，反解分析自己掌控 |
| 约束求解 | kiwi.js（Cassowary）起步，几何约束层自研牛顿法 | Cassowary 处理线性约束足够，相切等非线性约束需要几何求解器，P9 定去留 |
| 状态 | zustand + 自研响应式计算图模块（不依赖 MobX，求值需纯函数可控） | 计算图是核心资产，必须自有 |
| 成就引擎 | 自研模式匹配（数据驱动 YAML 模式库） | 见 03 章 |
| 存储 | IndexedDB（Dexie）→ P15 云端（Supabase 类 BaaS） | 本地优先，匿名可玩 |
| 部署 | 静态站点 + CDN；P15 起加 API | 网页端定位 |

## 第一幕 · 地基与魔法时刻（P1–P6）

> 目标：最快做出"画正弦波 → 建变量 a → 关联 → 拖滑杆波动了"这条最短闭环（剧本一），一切为这一刻让路。

| # | 里程碑 | 范围（做什么） | 验收标准（怎么算完） | 依赖 | 估时 |
|---|--------|---------------|---------------------|------|------|
| P1 | **技术验证原型** | Vite 工程；无限画布（平移/缩放/网格）；场景图数据结构；最小渲染循环 | 1000 条随机线段拖动平移缩放 60fps；坐标系与网格随缩放自适应 | — | 2pw |
| P2 | **基础绘制** | 选择/点/线段/圆/画笔五工具；选中、拖动、删除、撤销重做；吸附（网格+特征点） | 可徒手画三角形并整体拖动；undo/redo 覆盖全部操作 | P1 | 3pw |
| P3 | **参数系统** | 实体参数表（§3 数据模型）；右侧属性面板（读/写参数）；直接操纵（拖圆边改半径等） | 全部一期几何实体参数化；拖动部位 hover 高亮；属性面板双向同步 | P2 | 3pw |
| P4 | **变量与滑杆** | 变量 CRUD、滑杆卡、范围/步长；响应式计算图模块（拓扑序+脏标记） | 滑杆改值 → 计算图正确传播；100 节点图全量求值 <4ms | P3 | 2pw |
| P5 | **绑定引擎（前向）** | 绑定模型、表达式语言子集、两步关联器 UI、环检测、连接视图 v1（静态丝线） | **剧本一步骤 5–8 全流程通过**（魔法时刻 ✅）；成环给出人话拒绝 | P4 | 4pw ⚠高风险 |
| P6 | **函数生成器 + 预设库 v1** | 表达式输入（显函数）、mathjs 接入、未定义字母→滑杆建议；预设 6 个（正弦/余弦/抛物线/圆/三角形/单位圆） | 输入 `2x+3=y` 或 `y=a·x+b`（一键建滑杆）正确出图；预设拖入即用 | P5 | 3pw |

**第一幕出口标准**：内部 demo 可完整演剧本一；团队任何人 3 分钟内自发玩起来 = 继续，否则停下来复盘交互。

## 风险前置说明（为什么是这个顺序）

1. **P5/P7（绑定与反解）是全产品最大技术不确定性**（见 07 章），放在最前且各自独立验收——若 P7 反解体验做不顺，产品仍可靠"滑杆正向驱动"成立（剧本一不依赖 P7），**有降级退路**。
2. **成就引擎（P12）依赖实体/约束/绑定全部定型**，因此排第三幕，但模式库文案设计从第一幕即可并行（设计/产品岗）。
3. **知识网（P14）是情感峰值也是渲染峰值**，需要 P17 之前的 WebGL 决策——故 P17 紧随 P14。
4. 每个 ⚠ 高风险里程碑预留 30% buffer；连续两个里程碑超期即触发范围重审（砍预设数量/成就数量，不动核心闭环）。
